# Agent Ops: proposed first slice

The owner starts an accepted task once. A native operator carries it through
implementation, checks, independent review and authorized delivery. It asks the
owner only for decisions it cannot make within the accepted scope.

This is the qualification contract for [#143](https://github.com/arcitai/factory-software-defence/issues/143),
not an enabled unattended service. Use the existing native session, Factory CLI,
repository protections and ADLC skills. Keep the six installed skills unchanged.
Factory does not need a scheduler or another execution loop for this first slice.

## One bounded assignment

Retain the requested outcome, repository, source issue, accepted boundaries,
model/profile, verification and publication authority in the native session.
Reuse decisions already made. Read actual issue and native state before admitting
work; an issue label is neither execution authority nor proof of readiness.

Give each implementation one workspace writer and each independent review the
exact candidate and acceptance evidence. A native completed turn means ready for
review, not accepted, merged, released or installed. Re-review affected changes
after a finding or rebase. Preserve native session/turn identities through handoff.
If an operation has an unknown outcome, reconcile it instead of starting it again.

Use the selected Opus profile for substantial implementation or code review when
it is appropriate to the remaining judgment. Read quota as context; the native
harness decides whether execution is allowed. Stop at its limit. Do not switch
accounts, enable paid overage or infer remaining quota from token costs. A dollar
budget on a native CLI is not a subscription quota cap.

## When the owner is needed

- A material product choice or conflicting requirement has no accepted answer.
- A required action, destination or access boundary lacks authorization.
- A dependency or unknown outcome cannot be resolved with the available evidence.
- The agreed result is ready for a human decision, or a failure needs human action.

Routine reads, scoped fixes and already-authorized delivery continue without
repeated permission questions. Group related questions and present the concrete
candidate, evidence, recommendation and consequence of waiting. Distinguish
**published**, **installed** and **still open** in the final report.

## Communication boundary

Use the existing native chat for the first pilot. Run the lead session on the
Factory host, alongside its native workers; the chat is the operator's entry
point for progress and decisions. Record the actual execution host and native
session identity. A remote worker alone does not move the lead to that host.
Keep external messaging integrations for a separately qualified follow-up.

For a later messaging route, select its workspace, channel or recipient and
allowed human sender. Keep delivery credentials in the operator's
native connection, outside implementation workers. A message should identify the
task, exact candidate, checks, useful link and the decision needed. Suppress
unchanged notices; reconcile uncertain sends before retrying. Do not treat quoted
messages, webhook text, issue content or an unknown sender as new owner authority.
A reply must refer to the current decision and candidate; stale approval does not
apply to changed code. Keep a usable native session link if messaging fails.

No external messages or recurring schedules are enabled by this proposal. The
pilot must demonstrate authorized delivery and reply correlation with the chosen
route before unattended operation is advertised.

## Native capabilities and remaining proof

The native app owns remote and mobile access. Its [remote connection guidance](https://learn.chatgpt.com/docs/remote-connections)
describes a phone connecting through an online desktop host, which can then
reach an SSH development host. Verify that complete path and reconnection for
the selected installation; CLI availability on a remote machine is not proof
of a mobile-visible lead. Use native handoff/resume and preserve the session;
do not add a Factory chat relay or claim an untested connection is active.

The explicit [native Codex Auto-review mode](auto-review.md) is tracked in [#154](https://github.com/arcitai/factory-software-defence/issues/154).
It reviews eligible action approvals, while independent code/result review
remains part of the lifecycle. Existing Factory profiles retain their selected
permissions until the changed mode has installed qualification and deliberate
adoption. Auto-review availability alone does not authorize broader access.

[Claude channels](https://code.claude.com/docs/en/channels) provide an existing
inbound/reply route with sender allowlisting. The documented examples include
Telegram, Discord and iMessage; this is not evidence of a qualified Slack channel.
The current Factory execution profile excludes additional plugins/MCP and cannot
silently gain this authority. Qualify a separate operator connection.

[Claude scheduling](https://code.claude.com/docs/en/scheduled-tasks) depends on a
running session and recurring tasks expire. It is not proof of durable background
operation. [Claude routines](https://code.claude.com/docs/en/routines) run in a
cloud environment with explicit triggers and connector permissions; they are
not a drop-in supervisor for an existing local Factory installation. No routine
or schedule is needed for the one-assignment pilot.

The [comparison in #144](https://github.com/arcitai/factory-software-defence/issues/144)
provides the pinned T3 Code, Matt Pocock and Warp sources. Reuse native operation
boundaries, deliberate triage, exact-candidate review and a bounded retrospective.
Do not import a hosted orchestration stack. The video originally attached to
#143 could not be retrieved during this follow-up; its contents are not evidence.

Acceptance requires a real bounded task and the chosen communication route:
normal completion; actionable review finding; duplicate delivery; stale approval;
unauthorized sender; quota/auth failure; offline host; restart with unknown native
work; and uncertain message delivery. Keep source tests, rehearsal and real
installed proof distinct. Record what still needs the owner rather than claiming
that an absent human decision has been approved.
