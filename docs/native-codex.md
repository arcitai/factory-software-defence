# Native Codex pilot (#114)

This opt-in path uses Codex 0.155.1 `app-server` over JSONL stdio. Its app-server and named permission-profile contracts are experimental/beta. Keep the installed legacy controller available for its own evidence and rollback; native mode never falls back to its queue or executors.

```sh
factory native setup --repo /absolute/git/root --state /new/private/state [--codex /absolute/external/codex] [--bundle-read /absolute/runtime/bundle]
factory native login --state /private/state
factory native doctor --state /private/state
factory native serve --state /private/state [--port 7332]
```

Setup is Linux-only and requires a new state directory separate from the repository. It preserves the selected Codex invocation path and grants reads to the exact selected executable, its resolved target and the selected Node binary. Native ELF binaries and direct Node scripts are supported; other shims fail setup. A runtime that needs adjacent resources requires an explicit `--bundle-read` directory containing the resolved Codex executable: its binary directory or immediate installation root. Setup rejects broad top-level directories, the personal home, its ancestors and paths overlapping the repository or native state; review every bundle before granting it. No ancestor is inferred from an arbitrary binary. The dedicated HOME and CODEX_HOME contain the six packaged ADLC skills with an explicit read-only grant; scratch is writable. Setup records native trust for the explicitly selected repository so Codex does not rewrite the pinned profile on its first turn. The native `factory` permission profile denies root, allows minimal runtime reads, grants only the named runtime reads and scratch write, and grants repository writes while protecting `.git`, `.codex`, `.agents` and `VISION.md`. Command network is disabled. Apps, MCP, plugins, hooks, browser, computer use, image generation, tool suggestion and web search are disabled. No personal configuration or authentication is copied. Native login uses this selected environment; it is an operator action.

`app-server --strict-config` must accept the pinned profile. Doctor and admission recheck its file hash and native effective configuration, including layers, before any thread starts. `serve.lock` reserves one dashboard process. A repository-keyed writer lock under the OS account's canonical private home at `.local/state/software-defence-factory/native-writers/` (independent of the launch environment's HOME) coordinates issues and native state directories; a short gate serializes reconciliation. A later admission in the same state releases the prior writer only after native metadata readback confirms that exact recorded turn is terminal and no newer observed turn is active or unknown. This lock coordinates Factory clients; an independently launched native CLI in another environment remains the operator’s responsibility. Turn lookup is bounded to the latest 100 turns; an older unmatched turn remains unknown. Another state must be reconciled manually. Unknown or disconnected state blocks. A leftover gate or unresolved writer lock requires manual process and Codex-thread reconciliation; neither is discarded as stale. Directory separation alone is not OS isolation: the same user, owner and sudo retain their normal host power. Qualify actual skill discovery, effective permissions and negative access tests on the target Linux host.

Doctor asks native account, effective configuration, permission profiles, installed apps and MCP status, and reports gaps without account details or tokens. Unexpected effective layers or changed capabilities block admission. Start work is explicit from a refreshed GitHub issue with its expected content pinned. A small private receipt reserves the issue before `thread/start`; if a response or server disappears, the receipt remains unresolved and no automatic retry occurs. Codex owns session history and recovery. The Inbox's list, board, filters and issue detail remain; legacy execution controls are hidden. Reconnecting a known thread calls `thread/resume` only. Follow-up turns currently require the native Codex CLI; the Inbox does not pretend reconnect starts work. Unexpected native authority requests are refused and the active turn is interrupted where its identity is known. Dashboard HTTP remains loopback-only with Host, Origin and session checks. No generic RPC endpoint is exposed. App-server frames are bounded; raw native errors, commands, authentication and transcripts are not returned through HTTP.
